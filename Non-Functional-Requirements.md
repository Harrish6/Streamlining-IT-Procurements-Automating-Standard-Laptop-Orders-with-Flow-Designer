# Non-Functional Requirements

## Usability
The workflow should be understandable and easy for IT personnel to follow.

## Reliability
The flow should execute the configured actions consistently for valid requests.

## Maintainability
The workflow should be structured so that conditions and actions can be modified when project requirements change.

## Security
No passwords, authentication tokens, API keys, or confidential information should be stored in the GitHub repository.

## Traceability
The request status and fulfilment activities should provide enough information to understand the progress of the workflow.
